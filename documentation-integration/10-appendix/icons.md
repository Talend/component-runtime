# Appendix - Icons (`Icon.IconType`)

> Framework version documented: `1.2611.0-SNAPSHOT` (root `pom.xml`). Sources: `component-api/src/main/java/org/talend/sdk/component/api/component/Icon.java` (enum `IconType`, 247 constants) and `documentation/src/main/antora/modules/ROOT/pages/_partials/generated_icons.adoc` (245 generated entries). Catalog entries: `DSG-002`, `DSG-003`, `DSG-015` in [DSG catalog](../02-feature-catalog/DSG-design.md).

## Rules

- `@Icon(value = IconType.X)` exposes the icon string `key` (second column); `IconType.CUSTOM` with `custom = "name"` exposes `name`; `IconType.DEFAULT` exposes `default`.
- Constants annotated `@Deprecated` in the enum (column "Status in code") are legacy; new components SHOULD use `CUSTOM` with their own icon (enum javadoc: "recommended for custom components to use vendor specific icons and not reuse Talend built-in icons"). `STAR` is kept because it is used by the starter; `CUSTOM` is the default and only recommended mode; `DEFAULT` is `@Deprecated`.
- The designer MUST treat the icon as an opaque key (`DSG-003`). Built-in keys are served by the component server from its own classpath (`icons/<key>.svg` or `<key>_icon32.png`, optionally themed `icons/<theme>/`), custom keys from the plugin.
- Documentation note: `generated_icons.adoc` lists all 245 non-`CUSTOM`/`DEFAULT` constants with `"legacy": false` and path `_images/icons/svg/<key>.svg`; the enum marks all of them but `STAR` as `@Deprecated` (recorded as a docs/code discrepancy: the `legacy` flag of the generated page is not derived from `@Deprecated`).
