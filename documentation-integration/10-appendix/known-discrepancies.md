## 1. Confirmed facts (verified in code)

These six facts are the ones an integrator is most likely to get wrong. Each was re-verified by searching the sources.

| # | Fact | Verification | Impact for integrators |
|---|---|---|---|
| C1 | The Component Server has **no `ETag`, `If-None-Match`, `Last-Modified` or `Cache-Control` support**. Only an internal server-side JCache exists (`@CacheResult` on the resource implementations, `FrontCacheResolver`). No endpoint ever returns `304`. | No occurrence of these names in the Java, XML, properties or JSON main sources of `component-server-parent`. | A host MUST NOT send conditional headers nor expect validators. It SHOULD cache client-side keyed by URL + `language` and invalidate on `Environment.lastUpdated` / `connectors.pluginsHash` ([SRV-014](../02-feature-catalog/SRV-server.md), [SRV-017](../02-feature-catalog/SRV-server.md)). Any checklist item "caching (ETag)" is to be read as "client-side caching with `lastUpdated` invalidation". |
| C2 | `$maxDurationSeconds` **does not exist**. The technical options are `$maxBatchSize`, `$maxRecords`, `$maxDurationMs` and `$checkpoint.*` (plus the `maxRecords`/`maxDurationMs` parameter names of `@PostConstruct`, without `$`). | Repository-wide search for `maxDurationSeconds`: no match. Options are built by `MaxBatchSizeParamBuilder` and `StreamingLongParamBuilder`. | A host MUST render/send `configuration.$maxDurationMs` (milliseconds), never a seconds-based key ([CFG-016](../02-feature-catalog/CFG-configuration.md), [RUN-028](../02-feature-catalog/RUN-runtime.md), [RUN-040](../02-feature-catalog/RUN-runtime.md)). |
| C3 | The component (and configuration type) **version is a path/method argument**, not a configuration key. `POST /component/migrate/{id}/{configurationVersion}`; `ComponentManager.findMapper/findProcessor/findDriverRunner(plugin, name, version, configuration)`. For nested configuration types the version is carried by `<path>.__version` keys of the flat map. There is no `tcomp::component::version` key. | `ComponentResource#migrate` path parameter; no producer of `tcomp::component::version` in `src/main`. | Store the version next to the saved configuration and pass it as the path/method argument ([LCM-001](../02-feature-catalog/LCM-lifecycle.md), [LCM-003](../02-feature-catalog/LCM-lifecycle.md), [SRV-004](../02-feature-catalog/SRV-server.md)). |
| C4 | The default server has **no authentication**. Both `talend.component.server.security.connection.handler` and `talend.component.server.security.command.handler` default to `securityNoopHandler` (`NoopHandler`), which is the only accepted value. Any `Principal`-based checks are therefore no-ops unless the deployer replaces the handler. | `ComponentServerConfiguration` (`defaultValue = "securityNoopHandler"`), `NoopHandler`, `SecurityExtension`. | A production host MUST put authentication/authorization in front of the server (gateway, servlet filter, custom handler). The Designer MUST NOT assume roles or scopes exist ([SRV-019](../02-feature-catalog/SRV-server.md)). |
| C5 | `GET /api/v1/cache/clear` **mutates server state**: it redeploys plugins and clears caches although it is a `GET`. | `CacheResource#clearCaches`, implementation `FrontCacheResolver`. | Never call it from prefetchers, link checkers, health probes or generic GET crawlers; do not treat it as idempotent/safe; protect it ([SRV-016](../02-feature-catalog/SRV-server.md)). |
| C6 | The checkpoint switch is the JVM property **`talend.checkpoint.enabled`** (default `false`); the Antora page writes `talend.checkpoint.enable`. | `InputImpl` and `ComponentManager` read `System.getProperty("talend.checkpoint.enabled", "false")`; `component-checkpoint.adoc` says `enable`. | A runtime host MUST set `-Dtalend.checkpoint.enabled=true`; the documented spelling is silently ignored ([RUN-033](../02-feature-catalog/RUN-runtime.md)). |
